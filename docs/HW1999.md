# The 1999 hardware edition in detail

This complements [INSTALLERS.md](INSTALLERS.md#m4w240hwzip-the-1999-hardware-edition),
which describes the edition, what is missing and how close the existing
sources are. Here are the unit-level details: where each piece of 1999-only
code comes from, what the unknown units contain, the layout of the binaries,
the card driver's interface, and the French files.

"2.31" is the 2.31 tree in `old_versions.zip` (`m4w231/`), compiled as
described in [INSTALLERS.md](INSTALLERS.md#compiling-the-231-sources).
Addresses are `segment:offset` in the 1999 binary. Sizes are in
instructions ("ins").

## `INSTALL.EXE`

The 1999 `INSTALL.EXE` reproduces byte for byte, built by `setup.pas` as
`MAKE.BAT` runs it (which compiles `install.pas` with `/DShare` in 2006 too),
from the repository's sources with three differences:

- `winunit.pas`, in the font code: the temporary font file comes from
  `GetTempFileName(GetTempDrive('c'), 'm4w', 1, …)` and keeps its name (no
  `.FON` rename), and `ReleaseFonts` shows the "Could not remove font"
  warning (`IF NOT RemoveFontResource(…) THEN MessageBox(…) ELSE`, as the
  same code elsewhere in `winunit.pas` still does).
- `GetOS` is the 2.40 revision without the forced-NT ending (the `getos`
  edits of `tools/patches.py` without the last one).
- `W32Base` is the rebuilt unit without `{$C Fixed Preload Permanent}`, so
  it is moveable and the linker puts it in segment 1 after `User32`. In the
  1999 `MOD4WIN.EXE` and `PLAYER32.DLL` it is in moveable segments too.

## `MOD4WIN.EXE`

The 1999 `MOD4WIN.EX_` reproduces byte for byte: `setup.pas` with
`-u"2.40 Last Beta"` compiles `mod4win.pas` (`/Q /DCheck`), writes the user
name over the `DOOOVIEOFFLINE` placeholder (every byte inverted), stamps the
`Check` record (`BLOEDIE`) with the file size and checksum, and compresses
the file. The sources differ from the repository's in these places, besides
the `INSTALL.EXE` ones (`GetOS`, `W32Base`, the font code):

- **`mod4win.pas`, settings:** the 2.31 defaults (`OverrideRateChange` 0,
  `PauseWhileSetup` 1, `PlayOnLoad` 1, `NextPrevDelay` and `BlinkTime` 500,
  `BitsPerSample` 4, `Channels` 0, `OutputBuffers` 0, `TimerMode` 1,
  `Surround` 0, `OverSampling` 1, `SampleRate` `'44100'`), `LOG_ERRORS`
  default 1, `dev_GF1`/`dev_EWS` branches in the device `CASE` (default
  record and `Surround`), and the fallback chain GF1 → EWS → DAC → HDD.
- **`mod4win.pas`, elsewhere:** display mode 4 for GF1 and 6 for EWS (two
  places), `SR^.SetBMPZahl(44)` after stopping on GF1, and the 2006 changes
  undone: `getloadings` without the `bCancel` parameter (*Open → Cancel*),
  no `InvalidateRect` when leaving About, X/C stop playback before closing,
  no D key, the mini window kept on the screen, no local variables in
  `wmendsession`/`wmkeydown`.
- **`modc.pas`:** `dev_GF1 = -4`, `dev_EWS = -5`; the default records DAC
  (44,100 Hz, 24 buffers, timer mode 0, oversampling 2) and HDD (4 buffers),
  followed by GF1 (`'GF1 (e.g. Gravis Ultrasound)'`) and EWS (`'Dream
  SAM9407 (e.g. EWS64)'`, 37,500 Hz); `setcorrectwinpos` keeps windows on
  the screen (the 2.31 form).
- **`dsetup.pas`:** `DACID, GF1ID, EWSID, OPLID` (all set to 200), the
  GF1/EWS list entries, rate and buffer ranges, memory display, device
  branches and surround switch of 2.31 (without OPL4), and `'44100'` as the
  sample-rate default.
- **`playproc.pas`:** a procedure variable for player ordinal 500
  (`WINEWS_SETACTIVECARD`), declared after `mod_GetVersion`.
- **`winunit.pas`:** no umlaut replacement in bitmap fonts (no `Replace`).
- **`newopen.pas`:** `handleCancel` without the `wm_getloadings` message.
- **`REGDLG.PAS`:** without the empty `ELSE` branch, as `SHIPPED=1` makes it.

With these, every unit lands in the 1999 segment by itself, and
`RES_USA.DL_`, `INST_USA.DLL` and `M4W_USA.HL_` from the same `setup.pas` run
match too.

## `PLAYER32.DLL`

The 1999 `PLAYER32.DLL` reproduces byte for byte, compiled by `setup.pas`
(`/Q`) from these sources, besides the `MOD4WIN.EXE` ones (`modc`, `GetOS`,
`W32Base`):

- **`player32.pas`, `play.inc`, `loaders.pas`, `playdefs.pas`:** the places
  listed under [Where the 1999-only code comes from](#where-the-1999-only-code-comes-from)
  and in [INSTALLERS.md](INSTALLERS.md#how-the-2006-sources-differ-place-by-place).
- **`TrlNT`** without `GetFileName` and `FindDriver`, which are unit J's.
  **`PrtLayer`** has three more routines, `QueueInB`, `QueueOutB` and
  `QueueOutW`, which add a port access to the queue and flush it when full.
- **The hardware units:** `GF1`, `EWS` and `Dream` start from their 1996
  sources; B, `Sam9407` (E1), E2, F, G, H and I are written from the code.
  Their routine names are partly assumed.
- **`TPW.TPL`:** `GF1` and `Sam9407` call `GlobalAllocPtr` and
  `GlobalFreePtr` from Borland's `WinAPI` unit, which has the same code as
  `Win31`'s. In 1999 that code is in the fixed segment 1, so the run-time
  library of the build machine had `WinAPI` compiled with
  `{$C Fixed Preload Permanent}` too, like Strings, Win31, WinDos and OMemory
  ([BUILD_TOOLS.md](BUILD_TOOLS.md#tpwtpl-turbotpl-tpptpl-runtime-libraries)).
  No 2006 binary links `WinAPI`.

These details of the sources are there only for the layout
([MISSING_UNITS.md](MISSING_UNITS.md#layout-details) has the rules):

| Unit | Detail | Evidence |
|---|---|---|

## The `EWSAUDIO.DRV` interface

TerraTec's driver (from the January 1999 EWS64 L/XL CD, see
[INSTALLERS.md](INSTALLERS.md#developer-documentation)) is a thin layer over
`EWSAUDIO.VXD` from the same CD.

### The VxD

`EWSAUDIO.VXD` (134,322 bytes, LE format) declares the device `EWSAUDIO`,
device ID 0x3A3B, version 2.22. One API procedure serves both V86 and
protected-mode callers, which reach it through INT 2Fh function 1684h. It
dispatches on the caller's AX: AH (below 0x8A) selects an entry in an 8-byte
table (the highest allowed AL, then the handler), and AL is a sub-function.
Most handlers check the instance handle in the caller's EBX, map the caller's
buffer pointers to flat addresses (VMM `Map_Flat`) and call the C-compiled
part of the driver.

The SAM9407 is driven through two ports: each byte is written to the data
port after bit 0x40 of the status port (data port + 1) clears, with a time-out
of 1,000 polls. The voice-parameter routines send the firmware commands the
Linux driver documents: 0x56 (volume), 0x57 (main volume), 0x58 (pitch), 0x59
(aux volume) and 0x5A (filter).

### The `MOD*` exports

Each export loads a function number into AX, the instance handle into EBX
and its parameters into EDX, EDI, ECX and ESI, and calls the VxD:

| Export | Parameter bytes | VxD function | What the VxD does |
|---|---|---|---|
| `MODDEVOPEN` | 8 | 0x7D00 | checks the instance's state, then continues in the C part (not traced) |
| `MODDEVCLOSE` | 4 | 0x7E00 | not traced |
| `MODVOICESTART` | 8 | 0x7F00 | maps a caller buffer (`Map_Flat`), then continues in the C part |
| `MODVOICECLOSE` | 8 | 0x8000 | checks the voice number (below 63) and a flag (0 or 1), closes the voice |
| `MODVOICECHANGEPARAM` | 8 | 0x8100 | switches on the parameter type to the volume, aux, filter and pitch routines (firmware commands 0x56–0x5A) |
| `MODVOICEADDOFS` | 12 | 0x8200 | takes a voice, a sub-mode in CH and an offset; not traced further |
| `MODDEVCHANGEPARAM` | 8 | 0x8300 | not traced |
| `MODVOICESETLOOPSE` | 14 | 0x8200 | the same function with sub-mode 3 and a loop value in ESI |

`DRIVERPROC` handles the private messages with a chain of comparisons. Most
pass their parameters on to one VxD function; those marked * are the ones
region B sends.

| 0x42BC * | none: returns 0x020F0000 | 0x42D3 * | 0x1B00 |
| 0x42BD | none (a call inside the driver) | 0x42D4 | 0x1C00 |
| 0x42BE * | 0x0200 | 0x42D5 | 0x1D00 |
| 0x42BF * | 0x0300 | 0x42D6 | 0x1E00 |
| 0x42C0 | 0x0400 | 0x42DA | 0x1F00 |
| 0x42C1 | 0x0500 | 0x42DB | 0x2000 |
| 0x42C2 | 0x0600 | 0x42DC | 0x2100 |
| 0x42C3 * | 0x0700 (maps a caller buffer) | 0x42DD | 0x2200 |
| 0x42C4 | 0x0A00 | 0x42E4 | 0x2300 |
| 0x42C5 | 0x0800 | 0x42EE * | 0x0B00 (takes a pointer to a record of three doublewords; 87 if NIL) |
| 0x42C6 | 0x0100 | 0x42EF * | 0x0C00 |
| 0x42C7 * | 0x1300 (returns an instance field) | 0x42F1 * | 0x0E00 |

What the other functions do isn't traced: they run into the C-compiled part
of the VxD (about 115 KB of 32-bit code). For recreating region B it isn't
needed, because B's call sites fix everything its code depends on: the
message, the driver handle (from B's per-card table at 0x0354/0x0356), and
either constants or a pointer to a local record whose layout follows from
the stack offsets (0x42F2, for example, passes a record whose first word is
its own size, 0x6F). The VxD would only suggest names.

## The French files

- **`RES_FRE.DL_`** rebuilds byte for byte: the 2.31 `RES_FRE.PAS` (without
  the 2006 `dmo_usa.res`) with its 2.31 resources, compiled with `/DCheck`,
  then `CUSTOM\CHECKSUM.EXE` (which replaces the `Check` unit's `BLOEDIE`
  placeholder with the file size and checksum), then `COMPRESS`. The 1999
  `RES_USA.DLL` carries the same stamp.
- **`M4W_FRE.HL_`:** `HELP\M4W_FRE.BAT` of the 2.31 tree gives a help file of
  the same size (571,112 bytes) with the same text (`|TOPIC`) and bitmaps.
  The differences: the compile date in `|SYSTEM` (the original says
  1996-05-07 23:44:27) and about 30 bytes after it, about 2,000 bytes in
  each of `|CONTEXT`, `|KWBTREE` and `|TTLBTREE`, nearly all in unused page
  space (memory the help compiler doesn't clear), and 2,158 bytes in
  `|FONT`. The repository's `HELP/M4W_FRE.HL_` is a later file (227,437
  bytes compressed).
